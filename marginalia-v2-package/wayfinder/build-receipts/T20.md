## Corrections in revision 3 (chief review)

1. **A real margin can construct a request.** The service computed a
   `policyFingerprint` from absolute host paths and demanded the browser's
   `policyKey` equal it, which no margin could produce; the tests synthesised it
   with private host arithmetic. `policyKey` is now gone from the wire. Instead
   `POST /api/solver/prepare` takes six client-visible fields and returns an opaque
   nine-field plan — `planId`, a single-use 64-hex `planToken`, `limits`,
   `expiresAt`, `modelTurns: 0` and the three identities. `POST /api/solver/recompute`
   runs one prepared plan on the reader's explicit click. Preparation starts no
   process, calls no gate, spends no grant and writes no file.
2. **Idempotency is bound to content, and results are re-authorized.** Settled and
   in-flight lookups key on `solverRequestIdentity`, not on `requestId`. A
   `requestId` reused for different content is refused as
   `request-identity-mismatch`. Every settled or polled read re-authorizes at a new
   `result-read` stage and re-checks the host-resolved principal. Stated plainly:
   a bounded evicting map cannot make at-most-once restart-safe, so
   `SolverAttemptJournal` is specified for T06 and every record honestly reports
   `atMostOnce: 'process-local'` until one is mounted.
3. **Always streaming, and both streams checked.** A raw-byte budget cannot bound a
   buffered JSON reply, because one control byte becomes a six-character escape.
   `SOLVER_ALWAYS_STREAMS` replaces `requiresStreaming`, so every call streams at
   any cap. `stderr` `capReached`, `hostBoundReached` and byte overrun now each
   reject as `output-invalid`; previously only `stdout` was checked.
4. **The abort listener is removed.** The transport's named `onAbortEvent` listener
   is detached in `finally`, and a synchronous `rpc.request` throw becomes a
   rejection inside the same `try` so the same cleanup runs. Terminate semantics
   are unchanged: the acknowledgement is still not proof the process exited.
5. **A committed generation lease is required.** Hashing a solver is a point
   observation, not an immutability guarantee, and path hardening does not close
   the window. `finalize` must now return a `SolverGenerationLease` minted in the
   same transaction as the handoff; a wrong generation, a wrong manifest or a lease
   that lapsed mid-run refuses the result as `generation-drift`. Refusing saved
   solvers outright was rejected as a non-fix.

### Two real defects the new tests found

- `plan-expired` was unreachable: `request()` swept expired plans before looking
  one up, so an expired plan was reported as `plan-unknown`. The lookup now runs
  first.
- The durable journal branch refused a hit under a new `requestId` as
  `request-identity-mismatch`. The journal is keyed by content identity, so that
  is exactly the case it exists to catch. The id comparison is deleted.

What those tests actually establish:

- The only RPC method strings in `daemon/solver/**` are `command/exec`,
  `command/exec/terminate` and `command/exec/outputDelta`. A test asserts by name
  that `thread/start`, `turn/start`, `thread/resume`, `turn/interrupt`, `codex` and
  `codex-reply` are never sent. A model-turn policy throws before reaching the adapter.
- The service tests now drive the route with client-visible fields only: prepare,
  read the opaque plan, echo it at the click. No request is synthesised from
  host-private arithmetic.
- A plan carries exactly nine keys and no host-private value. Preparation
  dispatches nothing, commits nothing and writes nothing.
- Forged, borrowed, expired and spent plans all refuse. Changed inputs, state key,
  block, reply or solver between prepare and click give `request-identity-mismatch`,
  as does a `requestId` reused for different content.
- Permission-epoch movement, grant replacement, grant revocation, generation
  movement, source movement and a rewritten solver — each between prepare and click
  — refuse rather than run.
- `result()` is re-checked against current authority: revoked gives
  `authorization-refused`, expired gives `authorization-expired`, another tab or
  thread gets nothing. The route returns 401 without a host-resolved principal.
- A durable journal double prevents redispatch after the cache is cleared, and
  `atMostOnce` reads `'durable-host-journal'` with it and `'process-local'` without.
- A lease naming another generation or manifest, and a lease lapsing mid-run, are
  both `generation-drift`.
- `stderr` cap, host-bound and byte-overrun truncation each reject as
  `output-invalid` naming the stream.
- A completed attempt leaves zero `abort` listeners and sends no later `terminate`;
  a synchronous adapter throw is `unknown` with the listener removed; an abort
  racing the reply yields one outcome and one dispatch.
- Only the exact generated response shape is readable; five near-miss shapes all
  return `unknown` rather than a guessed success.
- A solver file edited after the job committed is refused as `artifact-modified`;
  a symlinked solver is refused; an interpreter inside the workspace it executes
  is refused.
- The commit order is asserted as
  `authorize:plan → authorize:dispatch → finalize → exec → authorize:accept`, and
  the attempt input file exists on disk when the gate decides.
- A cache hit reports `origin: 'cache'`, calls no gate, starts no process, still
  names the execution that produced the numbers, and is refused once authority
  withdraws.
- Failed, over-limit, unknown, cancelled and output-invalid outcomes never become
  cache entries. An unknown outcome is remembered and never silently retried.
- Cancelling a running attempt aborts the fence, discards the late result, reports
  the stop as unconfirmed, and leaves `.recompute/` empty.
- One case runs the solver through an unsandboxed local child process to prove the
  `solver --input <file>` protocol and the JSON round trip. It is labelled in the
  test as not the product path and not evidence of isolation.

## What is NOT verified

- **No real Codex `command/exec` call was made.** Shapes now come from the installed
  generated schema rather than guesses, but no live app-server answered this code.
  **Real process evidence is still needed**: no observed exit code, no observed
  `capReached`, no observed terminate acknowledgement.
- **No real isolation was demonstrated on any platform**, win32 included. Test
  evidence is a consistent fixture that exercises `auditCodexPolicy`.
- **Real memory enforcement is unsupported.** Codex 0.153.4 `CommandExecParams` has
  no memory parameter. A request declaring `maxMemoryBytes` is refused with
  `limit-enforcement-unavailable` rather than quietly ignored. No T20 change can
  fix this; it needs an upstream capability.
- **Process stop on cancel is unconfirmed on every platform.** Late output is
  discarded, never delivered.
- **At-most-once is process-local.** No durable journal is mounted, so an eviction
  or a daemon restart would let the same identity dispatch again. No product
  surface may promise a reader a single run until request 2e lands.
- **No generation lease exists.** The refusals are tested against a double. Whether
  T06 will hold a workspace generation immutable for a lease's life is unverified,
  and that is what closes the artifact-drift window.
- **Authority and context are unmounted.** Every dependency interface has no
  implementation and there is no allow-by-default fallback, so the product state
  today is "no recompute runs", reported honestly.

## Blocking integration work (proposed, not applied)

`docs/evidence/T20/integration.patch` carries the exact changes. None is applied,
because each touches a file another owner holds.

1. `daemon/server.ts` — mount `createSolverRoutes` and pass a `principal` resolved from the paired session, never from the request body.
2. T05 — speak the prepare/execute handshake: `POST prepare` with six client-visible fields, then `POST recompute` on the reader's click echoing the opaque plan. Eight fields that used to be on the wire are host state now.
3. T06/T07 — implement `SolverContextSource`. Needs a committed `solverSha256` and a `workspaceGeneration`; if the job store does not record the solver hash at commit time, that gap blocks any real demonstration.
4. T06 + T13 — implement `SolverExecutionGate.finalize` as the F20 transaction: non-consuming eligibility, then unique-once consume + authorization + egress + generation lease + handoff inside the JobStore's shared SQLite transaction, then the immediate runner call after commit.
5. T13 — implement `SolverAuthority` across five non-consuming stages (`plan`, `dispatch`, `cache-read`, `accept`, `result-read`) and `SolverEvidenceSource` reporting the backend actually in force on the running host.
6. T06 — implement `SolverAttemptJournal`: durable, keyed on `requestIdentity`, written before dispatch.

## Not accepted

T20 is not accepted. The route is not mounted, all five dependencies are
unimplemented, no real Codex process has ever run this code and no host isolation
evidence exists, so no zero-model-turn recompute has been demonstrated end to end
in the product. The module is finished; the wiring is someone else's to approve.
