## Requirements disposition

| Requirement | Disposition |
|---|---|
| Three to five reasoned items when authentic resources exist | Implemented. `verdict: ready` only for 3–5 kept items; more are truncated to the cap. |
| Never pad with inventions | Implemented. Items with no reason, no title, a non-public URL or a duplicate destination are dropped and flagged; thin shelves report honestly. |
| Preserve reason to open, source identity and return context | Implemented. Each kept item carries `title`, `reason`, `url`, optional `timecodeSeconds`; the assessment carries `returnTo`. |
| All items parked by default | Implemented. `parked: true` on the shelf and every item. |
| Creating/rendering a shelf must not fetch, navigate, download or infer | Implemented. `assessShelf` is pure and synchronous; it performs no IO. |
| Opening is an explicit host callback with validated URL policy | Implemented. `prepareOpen` returns a validated navigation request and performs no fetch; it re-checks HTTPS and non-private host. |
| Report fewer/insufficient real items honestly | Implemented. `verdict: insufficient` with a plain reason for 0–2 items. |
| Closed sessions perform no retrieval | Held. A shelf never retrieves, so it is valid in a closed session; the transform makes no network claim. |

## Public interface (for T05/T08 Pro integration)

```ts
assessShelf(reply: CandidateReply, context: ExploreContext): ExploreAssessment
prepareOpen(assessment: ExploreAssessment, itemId: string): OpenShelfItemResult
```

`context.returnTo` is `{ sourceVersionId, anchor }` from the thread the reply belongs to
(`contracts/reader.ts`). Required wiring (T05/T08 own the change): pass the thread's source version
and anchor as `returnTo`; render `assessment.items` as the parked shelf; on an explicit open action
call `prepareOpen` and hand the returned `{ url, timecodeSeconds, returnTo }` to the browser
open-and-restore path. The renderer already parks and links shelf items in `renderer/index.ts`
(`case 'shelf'`); this adds the validated open request and return context.

## Limitations

- URL reachability is never checked; a parked link may 404 when opened. That is a browser
  navigation outcome, not a shelf property, by design.
- Fixtures are labelled fixtures, not the real acceptance journey. No live navigation or browser QA
  was performed.

## 17 September 2026 — Explore navigation correction

Base: `86d658191cb6e8a6c1bd8bac45ec453c80a964e5` on `codex/wave-sol-explore`.
This section supersedes the public interface and authenticity wording above; the earlier results
remain the original worker's historical checks.

- A kept item is a **model-suggested link**, not a proven authentic or fetched resource. `ready`
  means three to five structurally usable, reasoned suggestions. A thin shelf remains parked and
  openable. Neither assessment nor URL construction proves reachability or grants permission.
- URL checks now preserve section fragments and accept public IPv6 literals, matching the existing
  reply navigation policy. Local/private literals and credentials remain excluded. Browser opening
  and broker retrieval have distinct policies.
- `prepareOpen(assessment, itemId, currentReturnTo)` now accepts only the original host-held
  assessment, checks it is parked and bound to the current source version and anchor, and uses an
  internal snapshot of the assessed item. A copy, stale context or later field mutation cannot
  substitute its URL or return context. The host must call it on the explicit reader click.
- The existing renderer still opens shelf links directly. T05/T08 integration must route that click
  through a held assessment and live reader context. This correction is an isolated contract, not
  a live stage-5a acceptance claim.
