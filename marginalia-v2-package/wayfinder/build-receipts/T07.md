Reply commit uses T03 validation against the thread's original source and generates a host report locally. It does not accept provider-supplied host attestations. Ask-on-note references an actual persisted note version and freezes its text. Parameter/view writes use separate optimistic revisions; they do not change the authored model, assumptions or host report. Replies have idempotent tombstones and undo. Reader mutations and reply/view changes write outbox events and replay receipts in the same SQLite transaction.

Journal changes retain optimistic work after a failed persistence call, reject the call, expose unsaved/persistenceError and prevent dispatch until durable. Retry is explicit and checks the last durable baseline, refusing to overwrite another tab's new saved state. Incoming load while unsaved neither replaces the draft nor advances that baseline. `reconcilePersistence()` is the explicit recovery path after another tab changes durable state: under the caller's shared Web Lock it adopts that state as authoritative, preserves local unsaved pending work and failed-ack overlaps as conflicts, saves once, and only then replaces memory. It never rebases or dispatches recovered drafts. `acceptCurrentConflict(changeId)` is the matching device-version acceptance path: it removes only the selected recovered conflict, records an `accepted-remote` resolution and preserves all pending upload intent, including work on the same thread. Stale-revision, missing-target and tombstoned-target note/thread edits are likewise persisted as conflicts before `change()` rejects, preserving the caller's editor draft and the current authoritative thread. Acknowledged mutation fingerprints prevent duplicate optimistic application; these are full canonical JSON identity records stored locally, not compact hashes. Conflicts are deduplicated and block only their thread; unrelated work can sync. Replacement resolution requires supplied remote state and an optional new-ID replacement with an explicit revision. Original and dependent drafts remain in conflict or resolution history. Legacy duplicate conflicts with a pending copy normalize to one conflict. Nothing automatically rebases a reader draft.

## Additive interfaces and coordination

Existing store apply/get/list/reattach/events/exportThread and journal load/change/sync signatures remain usable. The event envelope seq/kind/payload/createdAt is unchanged for T01 replay/live delivery.

- QuoteAnchor retains exact/prefix/suffix/start/end. Optional kind is quote/section/whole-page. wholePageAnchor() returns explicit page intent with empty quote and zero positions. It has no text candidates and is not highlighted. Empty ordinary quotes remain invalid. Reattachment now checks every available prefix and suffix for every exact-text candidate, including a unique candidate; quote text with mismatched frozen context is `unsure` with candidates rather than authoritative `exact` or `moved`. Context-free anchors retain weaker exact-text matching.
- SourceSection is exported as `{ title: string; start: number; end: number }`. SourceCapture and SourceVersion add optional `sections?: SourceSection[]`. Stored sections flow through `sourceVersion()` and the existing source/target-version export paths; the store never infers headings from prose.
- Store: sourceVersion, attachments, noteVersion, commitReply, reply, replies, replyView, saveReplyView, setReplyRemoved. reattach accepts optional fourth SourceCapture. Export adds attachments, targetVersions, replies and replyViews while preserving its existing fields/schema tag.
- Journal: unsaved, persistenceError, retryPersistence(), reconcilePersistence(), acceptCurrentConflict(changeId), resolveConflict(changeId, remoteThreads, replacement?). JournalState optionally adds resolutions and acknowledged. sync preserves conflicts and can complete while conflicts remain, so callers must inspect state.conflicts. All complete journal operations, including retry, reconciliation and conflict acceptance, require the same caller-held cross-tab Web Lock.
