## Delivered behavior

The trusted host prepares the exact bounded provider envelope before asking for consent. The preview shows each exact outgoing part, the recipient and the scope. Choices are this time, always on the exact origin, or never on the exact origin. Never is a durable, editable denial. Exclusions are independent and take precedence.

One-shot grants bind a request ID and prepared-payload digest, then atomically consume against one unique attempt. Every attempt receives a durable authorization and egress intent. Dispatch and result acceptance recheck the exact origin, current grant revision, monotonic site-permission epoch, denial, exclusion, provider, semantic policy and prepared payload. T06 integrated the same-database final acceptance callback. A permission fingerprint gives T06 the session-fork identity; a new grant revision, exclusion toggle, provider or policy produces a fresh provider session while the Marginalia thread remains related.

Egress records contain recipient, scope, provider, policy, context hashes, grant and revision, attempt, outcome and fetched-resource metadata. Events contain no raw page content. Browser code receives no Codex credential. Consent mutations accept only a server-constructed principal from a paired browser-owned margin or localhost settings surface; floating page-embedded UI has no grant controls.

The policy layer now uses a pinned reviewed profile per adapter, platform and operation. App-server bootstrap and dispatch evidence are distinct. MCP uses its own process/configuration evidence and keeps `schemaEnforced:false`, host parsing/validation, abandon-and-tombstone cancellation and unsupported restart recovery. Catalog status is observational and separate from an unsupported-capability veto. An incomplete catalog can still reveal and veto an unreviewed tool. The actual provider environment allowlist is admitted only with normalized key/value review and executable-resolution evidence.

The current official product home, `D:/MarginaliaRuntime/T02`, is signed out. Dedicated authentication, model-readable confinement, write confinement, closed tool-network and model-traffic separation evidence are absent. The bundled evidence source therefore rejects dispatch. No development exemption exists.

The retrieval broker accepts only HTTP(S) on ports 80/443, refuses non-public and local interface destinations, validates every DNS answer, pins the connection and verifies the connected peer, rechecks every redirect, bounds headers/body/deadline, accepts no caller headers or credentials, and records hashes rather than bodies.
