17 September 2026. This is the outgoing chief's acceptance assessment, not a marketing completion estimate. Read together with `CLAUDE-STEERING-HANDOFF.md` for paths, branches, model routing, preserved sessions and recovery, and `BUILD-STATUS.md` for integration chronology.

## How far along are we?

Marginalia has a substantial integrated foundation and some real, verified local reader flows. It is **not a completed alpha or launch-ready product**. The integration branch can build; its latest full suite reports 281 passes, no failures and one optional browser skip. Real Chromium checks prove selected capture, pairing, saved-note, offline recovery and management-request behavior. They do not prove a complete reading-to-Ask-to-interactive-reply loop, real saved-solver recomputation, host confinement, installation or the full designed experience.

There is no defensible overall percentage. Ticket sizes differ, several large capabilities remain queued, and unit-test volume would overstate user-visible completion. All 21 build tickets retain open acceptance work. Several have accepted implementation slices, not whole-ticket closure. The product's critical path is now runtime/consent/send correctness → live reply delivery → full margin UI → actual compute/evidence/explore flows → recovery/install/platform/launch verification. Small recovery corrections improved the product, but they must not distract the incoming chief from that path.

## Open-ticket review: priorities and technical judgment

**First priority: finish one real reader loop.** Close T06/T13 execution authority, bring in reviewed T05 design/provider controls and run Keep → explicit Ask → exact consent preview → provider output → source-bound reply → reload/cancel/recovery. Current static “Codex is not connected” messages and unmounted actions need live state, not cosmetic relabeling. Use fixture providers only to test state transitions, never as launch evidence of genuine execution.

**Second priority: make saved computation real.** T20's module is substantial but its completion claim is limited by missing host adapters and an unresolved atomic dispatch contract. Coordinate T06/T13/T07/T18/T05 against one exact integration revision. An opaque plan must bind the actual solver, input tuple, source, principal, generation and policy. Permission rechecks, durable attempt identity and generation immutability must hold at send and acceptance. Local compute must not spend cloud consent. Ambiguous dispatch remains unknown; no automatic replay or false stop confirmation.

**Third priority: protect reading and recovery.** C4 visible pairing lifecycle, C8 database migration safety, full export, diagnostics, library entry and honest current status are necessary alpha behavior. Backend success alone does not deliver the user experience. The current new routes rely on helper-origin browser trust/CSRF metadata, not protection from arbitrary native processes forging HTTP headers; preserve this stated threat boundary.

**Design review remains substantive.** Existing user-entry screenshots verify behavior, not the complete Claude design. Review all 14 frames and pass-2 states in light/dark, narrow widths, keyboard/focus and error recovery. Keep editor at reading position, notes senior to replies, a single complete map, no unsolicited sends, and human UI terms. Decide unavailable Hear-it visibility from source, without making unimplemented capability look usable. Docs Run copy must match actual execution policy.

**Cross-platform claims need actual evidence.** Architecture supports three targets; Windows-only runtime checks do not prove Linux/macOS compatibility or isolation. User can supply Linux and Mac tests. Finish portable executable/data/config handling and platform installers, then gather evidence. Do not substitute policy descriptions for observed enforcement.
