## Authority and the two settled layout decisions

SPEC-FINAL, the revised DESIGN-BRIEF-FINAL, FEATURE-INVENTORY and direct user decisions govern. The chief's `docs/DESIGN-PASS-2-INTAKE.md` records the user's latest answers:

- **Editor at the reading position, as in SPEC-FINAL.** The export's claim that a head editor was requested no longer governs. Keep a quiet source identity at the head; place the composer alongside the current reading position. Starting a draft freezes its visible attachment. Reading, selecting elsewhere or receiving a reply must not move that attachment implicitly. Changing it is an explicit action; saved notes retain anchor order.
- **One map, preserving all of that information.** Consolidate the overview while retaining note density, section boundaries, marks and current position. Expanded and collapsed presentations may differ, but neither loses the underlying information. Sending and working remain distinguishable from positional marks.

These are resolved decisions, not questions for another design review. The export's `.m-head:has(.m-editor)` allowance up to 78% of height is therefore not a direction to implement. The governing head remains a small identity region, within the spec's quarter-panel limit. The brief's one-line-until-focused note affordance is compatible with the reading-position composer.

## Preserve the visual language

Keep the already ported Claude tokens: warm restrained surfaces, compact editorial typography, full-ink reader notes, hairline separation, and coloured section navigation. Keep notes visually senior to assistant replies. Use excerpt size and spacing rather than low contrast to subordinate quoted context. Apply Impeccable/product and taste guidance as craft constraints; do not import marketing layouts, decorative cards or oversized headings into the reading tool.

Pass 2 supplies useful states and precise prose, but its CSS is a proposal. Reuse token roles rather than copy fixture-specific values. Existing contrast evidence predates these surfaces; it does not establish the contrast, focus visibility or zoom behaviour of newly composed controls. Source claims that the board was rendered elsewhere are not this task's verification.

## Minor refinements supported by existing requirements

These reconcile the board with settled behaviour and can inform later implementation without another product decision. They are not source changes in this assessment.

**Recipient and account copy.** The proposed “Codex on this computer, signed in to your ChatGPT account” obscures remote inference and assumes authentication. Both Codex transports launch a local process but use remote model inference. Chief/T06 report the dedicated runtime is currently signed out. Use the host-prepared `ConsentPreview.recipientLabel` bound to the actual recipient/provider. In a genuinely ready OpenAI-backed state, “Sends this context to OpenAI through Codex on this computer” is a clearer candidate. Show account detail only if observed for that runtime. The present signed-out state must remain unavailable. “All sends to Codex on this computer” must not suggest that inference stayed local.

**Permission boundaries.** Pairing authorizes the trusted connection, not inference or retrieval. A first inference grant does not activate automatic definitions. Existing links can be listed locally from the captured source; an agent fetching their contents still needs the narrower retrieval permission. Cloud-authored curation needs inference consent even when nothing is fetched. Pass only the preview's exact frozen request through decision and dispatch; edits invalidate it.

**Evidence language.** Adopt the chief's proposed relation labels only after the typed contract supports them. Tie each to the displayed claim and supporting passage. Do not convert them into verified truth, confidence scores, or a universal source rating. `FetchedResourceRecord` and `EgressRecord.retrievalComplete` provide the host evidence; the candidate's text or boolean does not. Promise a complete list of pages read only when the host can establish completeness. Otherwise label the record incomplete. The fixture's scientific prose is demonstration content, not research evidence.

**Truthful execution.** The docs frame's successful CLI transcript and elapsed duration cannot be used unless an actual execution record supports them. Until the isolated executor is available, show an example explicitly labelled “Expected output — not run” and an unavailable Run action. Retain the real execution feature in the implementation plan. For simulation, a saved sample view may say “Uses saved results; no new model request.” Local recomputation consumes compute and may call the helper; it is not literally no work or no network traffic. The host report's exact bounds determine a scientific headline: agreement over eight seconds does not establish behaviour beyond that interval.

**Source and exclusion states.** Unsupported selection cannot offer a successful highlight attachment without a valid selector; provide an explicit supported fallback or preserve an unattached draft. An excluded page cannot both promise nothing was read and display a newly extracted quote. Show saved work from its existing capture where permitted, with its provenance clear. Source hover/focus highlights; only an explicit navigation action scrolls. A current-page ambiguity never weakens validation against the original immutable SourceVersion.

**Responsive layout.** Treat native side-panel width independently from the floating host's browser viewport. The board's 900 px threshold is not a rule that every 360 px native panel becomes a different host. Target the 360/440 px references while allowing text reflow and zoom without losing actions. Long equations/code need a contained overflow strategy, not whole-panel horizontal scrolling. The fixture's six-digit flex row does not by itself implement the promised 3+3 wrap. Prefer one accessible, paste-friendly pairing input with visual grouping when possible.

**Focus and modal behaviour.** Keep focus on the initiating control/draft through background updates; return it to a connected opener after dismissing a sheet. Do not declare a sheet `aria-modal=true`, trap focus, and simultaneously promise that the rest of the same document remains freely operable. Define the boundary: a true modal blocks its document's other content; a nonmodal sheet permits deliberate keyboard return to the page. Separate native host documents do not make the article part of the sheet's focus cycle. The page-embedded fallback still cannot authorize privileged sends. No keyboard, screen-reader, zoom or reduced-motion result is verified here.

**Unavailable capabilities.** Hear it unavailable was already approved in DESIGN-FEEDBACK-PASS2 item 19 and INTERACTION-ACCEPTANCE. Do not fire a success toast or silently substitute another action. Keep its eventual capability in scope. Likewise derive sign-in and recovery instructions from the actual adapter/health state; the design's app-specific instruction is not universally correct. Ctrl+Shift+Y remains a proposal, not a verified shipped shortcut.
